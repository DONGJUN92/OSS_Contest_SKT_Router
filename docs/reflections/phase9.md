# Phase 9 Self-Reflection — 실데이터 접속 준비 (백로그 B1·B2)

날짜: 2026-07-18 · 상태: **완료** · 산출: `src/loader.py` · `docs/branch_decision_table.md`
· `tests/test_loader.py`

## 배경

Phase 8로 통제 가능한 리스크는 소진됐고 남은 것은 실데이터 고유 분포뿐이다. 그러나
"수령 후 대응"과 "수령 당일 연결"은 다르다. 이 사이클의 목표는 **데이터가 도착한 날
생각할 것을 0으로 만드는 것** — 답변 분기표(B1)와 로더(B2).

## B2 — 로더 (`src/loader.py`)

설계 원칙은 Phase 8의 접속 계약을 그대로 재사용하는 것이었다: 로더는
`textworld.to_dataset`과 **동일한 `(Dataset, meta)` 쌍**을 낸다. 그 결과 verifier·
encoder·엔진·하네스·라우터가 한 줄도 바뀌지 않는다.

흡수한 미지 요소 3종:

| 미지 요소 | 흡수 장치 | 코드 수정 |
|---|---|---|
| 파일 포맷 | 확장자 판정 (JSON/JSONL/CSV/TSV/parquet) | 0 |
| 컬럼명 | `FieldSpec` 값 (`--map quality=score`) | 0 |
| 레이아웃 | `wide_to_long()` (1행=쿼리 → 1행=쿼리×모델) | 0 |

`validate_dataset()`은 형상·범위·NaN·비용 양수·(쿼리×모델) 완전행렬·샘플 균일성을
assert하고, 통과 시 리포트에 **Q2·Q4 분기 판정**을 실어 보낸다 — 즉 6개 질문 중 2개는
주최측 답변 없이 데이터가 스스로 답한다.

## ★ D16 — 불균일 샘플 수의 조용한 비용 오염 (테스트가 먼저 잡음)

초기 구현은 셀별 샘플 수가 다를 때 `k = min(N, len(samples))`로 **조용히 축소**했다.
이 경우 `#v5` 상자는 프리필 5배를 과금당하면서 실제로는 4표만 집계한다 — 비용은 그대로,
상금은 낮아지는 **점수 오염이 경고 없이** 발생한다. 합성 세계에서는 S가 항상 균일해
드러날 수 없는 결함이고, 실데이터에서야 나타났을 것이다.

수정: `build_dataset`이 샘플 수 균일성과 인덱스 연속성(0..S−1)을 강제하고 위반 시
`SchemaError`로 즉시 중단 — 절단·보완의 판단을 사람에게 돌려준다.

발견 경로가 중요하다. 이 결함은 코드 리뷰가 아니라 **왕복 동일성 테스트를 설계하다가**
드러났다. "로더 출력이 원본과 한 치도 달라선 안 된다"는 기준을 세우자 `min()` 축소가
그 기준을 어기는 지점으로 즉시 노출됐다. D6/D10/D11(공학적 결합부가 정책을 무효화)의
반복이며, 대응도 같다 — 불변량을 테스트로 못 박는다.

## 회귀 방벽 (`tests/test_loader.py`, 10종 → 전체 20/20)

| 검증 | 내용 |
|---|---|
| **왕복 동일성** | World F → 레코드 직렬화 → 로더 복원이 원본 Dataset과 quality·out_tokens·in_tokens·domains·vote_share·rep_text·가격 전부 일치 |
| 포맷 등가 | JSONL / JSON / CSV 세 경로가 동일 Dataset 산출 |

| 분기 판정 | S=1 → Q2=NO 축소 / 연속 품질 → Q4=B4 필요 |
| 위반 탐지 | 범위 이탈·NaN·필수 필드 누락·불완전 행렬·중복·불균일 샘플·단가 미상·미지원 포맷·features 미부착 |
| **수령 당일 경로** | 로더→인코더→verifier→라우터→하네스 전 구간 통과 + 예산 초과 0 |

마지막 항목이 이 사이클의 핵심 자산이다. 런북이 문서로만 존재하면 수령일에 깨질 수 있지만,
**경로 자체가 테스트라서** 매 실행마다 재검증된다.

## B1 — 분기 결정표 (`docs/branch_decision_table.md`)

작성 과정에서 확정된 사실 3건:

1. **실제 문의가 필요한 것은 Q1·Q3·Q5·Q6 4건뿐** — Q2·Q4는 로더가 데이터에서 판정.
2. **미구현 분기는 Q4=연속 하나뿐** (B4: Beta 상금 예약값 수치해). 나머지는 플래그
   (Q2·Q6) · 설정 (Q3) · 1~2줄 (Q1) · 소규모 스위치 (Q5).
3. **무응답 리스크 없음** — 답변이 끝내 오지 않아도 현행 기본 가정 조합이 그대로 제출
   가능하며, 그 조합이 6세계에서 검증된 구성이다.

3번은 사이클 시작 전에는 확신할 수 없던 것이다. Phase 0을 "블로킹"으로 분류해 뒀으나,
매핑을 끝까지 그려보니 **블로킹이 아니라 최적화 항목**이었다. 리스크 레지스터의
R1·R4·R5가 설계 단계에서 이미 우아한 퇴화 경로를 확보해 둔 결과다.

### 초안에서 잡은 서술 오류 — 구현 부채 ≠ 검증 부채

초안은 Q2=No를 "0줄, 서열 유지(A~E가 단일 샘플 기준 검증)"로 적었다. 코드로 확인하니
**거짓**이었다: `run_phase4.py:ext_worlds`가 6세계 점수표를 전부 `extend_with_votes`로
만들므로 단일 샘플 서열 검증은 Phase 3b의 World A·B까지뿐이다. Q2=No는 코드 0줄이
맞지만 C·D·E·F 점수표 재산출을 요구한다.

여기서 표를 두 축으로 나눴다 — **구현 부채**(코드를 써야 하는가)와 **검증 부채**(실험을
다시 돌려야 하는가). 이 구분이 없으면 "0줄"이라는 표기가 수령일에 안심의 근거로 오용된다.
Q2=No와 Q6=force_cheapest가 정확히 그 함정에 해당한다.

- `eval/results/final_scores.json`이 Phase 6 시점(0.9490)에 멈춰 있던 것을 Phase 7 이후
  현행값(0.9481)으로 갱신. PROJECT_PLAN의 0.9490은 Phase 6 이력 기록이므로 정정 대상 아님
- `SUBMISSION.md`의 M4 인증서 예시가 8.2%/0.6%로 적혀 있었으나 실측은 0.0838/0.0062 —
  **상한값을 내림 표기하면 보증을 과장**하게 되므로 8.4%/0.7%로 정정(올림)

또한 실행 방식 자체에서 함정 하나를 확인했다: `timeout N python ... | tail`은 파이프 시
파이썬이 블록 버퍼링을 하므로 **중도 종료 시 출력이 통째로 사라지고 파이프라인 exit code는
`tail`의 0**이 된다. 실패가 성공으로 보인다 — 장시간 실행은 `python -u`로 돌릴 것.
