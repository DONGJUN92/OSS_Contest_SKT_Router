## 배경 — 전체 스캔이 phase-log에 없던 것을 드러냈다

Phase 1~12는 합성/실텍스트 검증 트랙을 닫고 "남은 것은 실데이터 + 주최측 답변뿐"이라고
결론지었다. 그런데 대회 상세(사용자 제공)를 코드와 **대조**하니 계획에 없던 제약이 나왔다:

> **런타임 라우터가 보는 정보에서 "benchmark 또는 task 이름"은 제외된다.**
> (제공: prompt/messages · budget tier · 모델 프로파일·비용 · 호출 이력 · 반환 출력 ·
>  토큰/비용 · 남은 호출 수·예산. 미제공: **task 이름** · source repo·row id · fingerprint)

이는 현행 설계와 정면으로 부딪힌다. 우리는 **다집단 2PL**(도메인별 난이도 `b_{d,m}`)을
쓰고, 제출 어댑터는 도메인 미지정 시 일부러 예외를 던진다(D18). 공개 데이터에는 도메인이
있어 **적합은 되지만**, 추론 시점에 도메인 라벨이 없으므로 배포 경로가 동작하지 못한다.

★ **왜 지금까지 안 보였나 — 하네스가 런타임이 주지 않을 것을 공급했다.** 오프라인 평가
하네스는 매 쿼리 `int(ds.domains[i])` 를 정책에 넘긴다. 합성·textworld 데이터가 도메인
라벨을 들고 있어 6세계 매트릭스 전부가 이 갭을 **가린 채** 통과했다. D16(불균일 샘플)·
D17(σ<0)이 "테스트 통과 ≠ 테스트가 덮는 영역"이었듯, 이번엔 **평가 환경이 배포 환경보다
관대**해서 갭이 안 보였다. 배포 API(`submission.step`)를 직접 들여다봐야만 드러난다.

## 결정의 재구성 — 단일집단은 "선택지"가 아니라 배포 구성이다

런타임에 도메인이 **아예 없으므로**, 두 가지가 명확해진다:
- **단일집단(`use_domain=False`)** 은 대안이 아니라 우리가 비공개셋에서 **실제로 돌릴 구성**이다.
- **다집단**은 도메인이 주어졌을 때만 가능한 **오프라인 상한(ceiling)** 이다.

즉 우리가 보고해야 할 "실제 기대 점수"는 단일집단 열이고, 다집단 열은 참고선이다.
`use_domain=False` 는 다집단을 단일집단(`b_m`)으로 퇴화시킨다 — 리스크 레지스터 R2/R5식
**우아한 퇴화**이며, `irt["b"]` 가 `(1,M)` 이 되어 제출 어댑터의 D18 예외도 자동 해소된다
(`n_domains==1` → `domain_of` 기본값). 적합은 여전히 공개 데이터로 하되 도메인 축을 풀링한다.

**핵심 판독**:
- **가장 현실적인 세계(textworld)에서 단일집단 비용 = −0.0004** — 실텍스트·실출력·실검증기
  조건에서 도메인 상실은 사실상 무의미하다. 특성이 텍스트 인코더 출력이라 도메인 원-핫이
  특성에 새지 않는 **가장 깨끗한 세계**의 값이라 신뢰도가 높다. nosignal·crossing도 ±0.001.
- **손실은 도메인 구조가 강한 두 적대 세계에만** 있다: specialist −0.0079(fast −0.0149),
  corr −0.0053(balanced −0.0205). 둘 다 합성 세계이고 도메인이 특성에 원-핫으로 박혀 있다.
  실제 후보는 A.X-3.1-Light/3.1/K1-Think **크기 사다리**라 이런 도메인 역전·특화가 나타날
  가능성이 낮다.
- **서열은 유지된다**: 단일집단도 라우팅 구조가 중요한 4세계에서 cascade를 크게 앞선다
  (irt +0.26, corr +0.05, nosignal +0.17, textworld +0.18). cascade가 근소 우위인
  specialist·crossing은 **다집단에서도 이미** 그랬고(−0.0003/−0.0028), 모든 정책이 ~0.99로
  뭉치는 easy 세계다. 단일집단이 specialist 격차를 −0.0003→−0.0081로 벌리지만 정성적 그림은
  불변이다.

**판정**: 단일집단을 **정직한 배포 기본값**으로 채택한다. 프롬프트→도메인 분류기는
**실데이터 전에는 정당화되지 않는다** — ① 도메인이 중요한 두 세계가 비현실적 합성 인공물
(크기 역전 + 도메인이 특성에 박힘)이고 ② 현실 세계(textworld)의 비용이 0이며 ③ 분류기는
v5의 "탐색 표면적 축소 = 분포 이동 방어" 원칙에 반해 과적합 표면적과 실패 모드를 늘린다.
다집단 적합과 `use_domain` 플래그는 **보존**하므로, 실데이터가 "도메인이 중요하고 텍스트로
추론 가능"함을 보이면 그때 `domain_of`(프롬프트→도메인) 만 구현하면 된다.

## ★ 단일집단이 드러낸 잠재 결함 — 도메인 인덱스 클램프

측정 도구를 돌리자마자 `run_diagnostics.prior_pbar_row` 가 `router.irt["b"][dom]` 에서
`IndexError`(dom=3, size 1)를 냈다. **D17·D18과 정확히 같은 "단일집단에서 도메인 인덱스"
결함 계열**이다. 단일집단이면 `b` 가 `(1,M)` 인데 소비처가 다집단을 가정하고 `dom` 으로
직접 인덱싱한 것이다.

전수 확인 결과, 이 패턴은 4곳에 있고 **단일집단 배포 경로를 타는 2곳만** 수정 대상이었다:
- `src/router.py:make_belief` — 클램프 적용 (배포 정책의 심장)
- `run_diagnostics.py:prior_pbar_row` — 클램프 적용 (측정이 이 경로를 탐)
- `run_phase3.py:make_pandora` · `eval/probe_update_corr.py` — **다집단 IRT를 자체 생성하는
  ablation 전용 도구**라 단일집단 라우터를 받지 않는다(트리거 안 됨). 무변경.

이번엔 **크래시(loud)** 라 조용히 틀리진 않았지만, 근원은 같다 — 단일집단이라는 새 모드가
기존 코드의 암묵적 다집단 가정을 드러냈다. 대응도 일관된다: 소비처에서 형상 기반 클램프.

## 검증기 태스크 일반화 (`src/verifier.py`)

phase8과 branch_decision_table이 지목한 "유일한 남은 개선 경로"의 실데이터 대비판이다.
현행 `extract_features` 의 구조 검사·도메인 원-핫만 textworld 4태스크(정렬/JSON/세기/산술)에
하드코딩돼 있어, 미지의 실도메인에서 무력하거나 오작동한다.

일반화(라우터 `use_domain` 퇴화와 같은 철학):
- 구조 검사를 `STRUCT_CHECKS` dict로 분리하고, **미지 태스크는 타입-일반 폴백**
  (`_generic_struct`: 탐지된 답 타입의 well-formedness — 파싱되는 JSON/수/수열 1.0, 짧은
  토큰 0.7, 장황한 산문 0.3, 공백 0.0). 정답 여부(정렬성 등)는 태스크 지식이 필요하므로
  포기하고 형식 품질만 잡는다("오답은 형식 파괴를 동반"이라는 신호).
- 도메인 원-핫을 **데이터 주도**로: `feature_matrix` 가 데이터의 유일 도메인에서 어휘를
  도출한다(모든 task가 TASKS면 TASKS 고정 → textworld 비트 동일).

★ **하위호환을 AUC가 아니라 특성 수준에서 증명**했다. textworld의 모든 task는 `STRUCT_CHECKS`
에 있고 도메인 어휘 기본값이 TASKS이므로, textworld 특성 벡터는 **비트 단위로 불변**이다 —
따라서 AUC(0.90)·기존 결과·재현성이 자동 보존된다(값비싼 재측정 불요). 미지 도메인은
크래시 없이 타입-일반 신호 + 실도메인 원-핫을 얻는다. 회귀 2종으로 양쪽을 고정.

## 논문 신규 레버 검토 (adaptive-N · prefix-sharing) — 적대적 검증

참고 논문(2408.00724 Wu et al. 투표 포화, 2406.16838 §7 prefix sharing)이 제시한 두 레버를
현 코드 대비 분석하고 **적대적 검증**했다(독립 분석 2 + 리퓨트 4 + 종합 1 에이전트). **양
verdict 모두 유지**(4/4 refuted=false)되, 검증자들이 정확한 정정을 embed했다.

**Lever 1 — adaptive-N (Wu 마진 경계 + Aggarwal 조기중단): SUBSUMED → 무조치.**
사전계산 원자 박스라 생성 제어(draw→check→draw)가 애초에 적용 불가하다. 그 정신은 이미
두 방식으로 실현돼 있다: ① Weitzman이 `#v1`을 열고 σ 재계산 후 `#v3/#v5`가 이길 때만 승급
(pandora.py:259-266), ② `vote_share`가 verifier 특성(verifier.py:108,133)으로 이미 사용 —
Wu의 느슨한 상한 `|A|exp(−nδ²/2)`(미지 |A|·δ, N=1에선 계산 불가)보다 데이터 보정이 우월.
- 적대적 정정(verdict 유지): 유일한 sliver인 "재사용 회피"는 프리필뿐 아니라 **디코드도**
  환불(디코드 지배라 ~3.5배 큼)이고, 막는 것은 "단일 사전계산 액션 규칙"이 아니라 **액션
  집합에 increment-N이 없다는 것**(cost_mirror가 열마다 원자 과금). 즉 sliver는 더 크지만
  더 확실히 실현 불가 — 둘 다 drop을 가리킴. "N=2 동률=오답" 리스크는 stale docstring 오류
  (실제는 무작위 해소, synth_ext.py:59-63). **무조치.**

**Lever 2 — prefix-sharing 비용 현실성: DEFER → Q3 게이트 스텁(기본 OFF) + prize 실측.**
프리필이 `pf*N`으로 저장(synth_ext.py:73 등)돼 있고 디코드는 이미 N배라, 공유 시 프리필만
`N→1`로 준다. **과대비용은 실재·정량화됨**: vote box가 ~20-30% 과대(최저가 40%, 프롬프트
tail 1.8-3.5배; 실측 wiring: xl#v5 −21.7%, tiny#v5 −31.9%). 그러나 **위험이 비대칭**이다 —
과대비용(현행)은 투표를 약간 덜 쓸 뿐이나, 공유를 가정했다가 host가 N-prefill을 청구하면
c가 20-40% 낮게 잡혀 투표 상자 과다개봉 → 비공개셋 실채점에서 **가중치 최고 fast tier
예산 초과**. 이득은 조건부(EV = P(host 공유)×이득, N-prefill이면 정확히 0 — 정책이 어떤
비용에도 λ로 적응해 "남는 것"이 없다). 게다가 tier 예산=frac×(최대 상자 비용)이라 공유가
켜지면 예산도 줄어 상쇄가 있다 → **산술 상한이 아니라 실측 필요**.
- **구현(코드베이스 Q-분기 관례대로 스텁, 기본 OFF)**: `cost.prefix_sharing`(config) +
  `cost_mirror.vote_prefill_mult(cfg,n)` 중앙 헬퍼를 vote-box 3소비처(synth_ext/loader/
  textworld)에 접속. `cost_mirror`의 산식 자체는 무변경(프리필 배수만 조정). 하위호환(기본
  OFF=현행 pf×N) + ON 동작 + N=1 불변을 회귀 2종으로 고정. **Q3에서 공유 확인 시 config 한
  줄만 켜면 됨.**
- ★ **prize 실측 완료**(`eval/probe_prefix_sharing.py`, 6세계 5-fold) — **예상과 반대로 ON이
  나쁘다.** Δ(ON−OFF): irt **−0.0183** / specialist −0.0067 / corr −0.0157 / crossing +0.0012 /
  nosignal −0.0084 / textworld **−0.0164**, 손실이 **fast tier에 집중**(irt fast −0.035).
  (OFF 열이 정준 스코어보드와 정확히 일치 — 측정 신뢰.)
  **원인**: tier 예산 = `frac×(최대 상자 비용)`(harness.tier_budgets)인데, 공유가 켜지면
  최대 상자(xl#v5)가 22% 싸져 **예산 절대액이 함께 줄어든다**. 그런데 저예산 라우팅이 기대는
  **N=1 단일호출 상자는 공유로 안 싸진다**(프리필 1회 그대로) → 투표 할인이 예산 축소를
  상쇄하지 못하고, 예산이 조이는 fast>balanced에서 손해(premium은 예산 넉넉→~0).
  **함의**: prize는 양수가 아니라 **음수**이며, 이는 우리 예산이 **상대적**(frac×비용)이라
  비용을 낮추면 예산도 같이 낮아지기 때문이다. host가 **절대 예산**이면 부호가 바뀔 수 있다 —
  즉 채택은 Q3(host 공유)뿐 아니라 **Q7(예산이 상대/절대)에도 이중 의존**한다. 적대적 검증의
  "likely zero"를 넘어 **상대예산에서는 실측 손해**임이 확인됐다: 비대칭 위험 + 측정 손해 →
  **스텁은 준비하되 기본 OFF 유지가 옳다**가 실증으로 확정. Q3·Q7 둘 다 유리해야만 재검토.
